# OpenObserve Provider

Manage [OpenObserve](https://openobserve.ai) declaratively: organizations, streams,
dashboards, alerting, service level objectives, and identity and access management.

## Example Usage

```terraform
terraform {
  required_providers {
    openobserve = {
      source  = "openobserve/openobserve"
      version = "~> 1.3"
    }
  }
}

provider "openobserve" {
  endpoint = "https://openobserve.example.com"
  username = var.openobserve_username
  password = var.openobserve_password

  # Used by every resource that does not set org_id itself.
  org_id = "default"
}

# Credentials can also come from the environment, which keeps them out of the
# configuration entirely:
#
#   export OPENOBSERVE_ENDPOINT=https://openobserve.example.com
#   export OPENOBSERVE_USERNAME=admin@example.com
#   export OPENOBSERVE_PASSWORD=...
#   export OPENOBSERVE_ORG_ID=default
```

## Organization scoping

Every resource and data source takes an optional `org_id`. Leave it unset and the
provider's own `org_id` is used, so a single-organization setup never repeats it:

```hcl
provider "openobserve" {
  org_id = "default"
}

resource "openobserve_stream" "app_logs" {
  # No org_id: inherits "default" from the provider.
  name        = "app_logs"
  stream_type = "logs"
}

resource "openobserve_stream" "team_logs" {
  # Explicit override for a second organization.
  org_id      = openobserve_organization.team.identifier
  name        = "team_logs"
  stream_type = "logs"
}
```

## Editions

Custom roles, groups, and the permission resource list require OpenObserve
Enterprise with OpenFGA enabled. Against an open-source deployment those
resources return a diagnostic saying so, rather than an opaque HTTP 403.
Everything else, including SLOs, works on both editions.
